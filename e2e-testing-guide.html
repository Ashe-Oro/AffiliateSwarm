Regata — E2E Testing Guide

Venice Agent Affiliate Platform • POC • February 2026

Overview

This guide walks you through a complete end-to-end test of the Regata platform. You will play three roles across two machines on the same home network.

Role Machine What you do
Venice Platform Your Mac (192.168.4.89) Start the Regata server, run the automated test script
OpenClaw Agent Other computer (same LAN) Point OpenClaw at the SKILL.md URL to test agent onboarding
Human (You) Either machine (curl / browser) Simulate a referred user clicking, signing up, and purchasing
┌─────────────────────┐ LAN ┌─────────────────────┐ │ Your Mac │ ◄──────────────────► │ Other Computer │ │ 192.168.4.89:3000 │ │ OpenClaw Agent │ │ │ │ │ │ Regata Server │ GET /SKILL.md │ Discovers program │ │ SQLite DB │ ◄────────────────── │ Registers itself │ │ SKILL.md │ POST /api/register │ Runs heartbeat │ │ HEARTBEAT.md │ ◄────────────────── │ Logs activity │ │ │ GET /HEARTBEAT.md │ Checks earnings │ └─────────────────────┘ └─────────────────────┘

Prerequisites

Node.js installed on your Mac
Both machines on the same home network
OpenClaw installed on the other computer
curl and jq available on both machines
Your Mac's LAN IP is 192.168.4.89 (re-check with ipconfig getifaddr en0)
IP Address: If your Mac's IP has changed, update platform/skill.md, platform/heartbeat.md, e2e-test.sh, and platform/src/server.ts before proceeding. Search and replace 192.168.4.89 with your new IP.

Phase 1: Start the Platform

Venice Platform — On your Mac

1
Install dependencies and build
cd ~/Projects/veniceAI-regata
npm install
cd platform
npm run build
Build completes without errors
2
Delete old database (fresh start)
rm -f platform/data/regata.db
This ensures a clean slate. Skip this if you want to keep existing data.
3
Start the server
cd ~/Projects/veniceAI-regata/platform
npm start
You see the Regata startup banner with http://0.0.0.0:3000
Banner shows LAN: http://192.168.4.89:3000
4
Verify it's reachable (new terminal tab)
curl http://192.168.4.89:3000/health
Returns {"status":"ok", ...}

Phase 2: Run the Automated Test Script

Venice Platform — On your Mac (new terminal tab)

This script exercises the full API: register, authenticate, post, refer, signup, purchase, earn, payout. Run it before involving the other machine.

5
Run the e2e test script
cd ~/Projects/veniceAI-regata
bash e2e-test.sh
All 27 assertions pass (green checkmarks)
Summary shows ALL 27 TESTS PASSED
If all tests pass, the platform API is fully functional. You can now test with the real OpenClaw agent.
If tests fail: Check that the server is running, the IP is correct, and the database was deleted for a fresh start. The test script creates its own agent, so stale data shouldn't matter, but a clean DB is safest.

Phase 3: Agent Discovery & Registration

OpenClaw Agent — On the other computer

This phase tests whether a real OpenClaw agent can discover the SKILL.md, self-register, and save credentials.

6
Verify network connectivity from other machine
curl http://192.168.4.89:3000/health
Returns {"status":"ok", ...}
If this fails, check that both machines are on the same network and no firewall is blocking port 3000.
7
Agent fetches SKILL.md

Point OpenClaw at the SKILL.md URL. How you do this depends on your OpenClaw setup. Options:

Option A: Feed the URL directly to the agent

# In OpenClaw's chat or prompt:
"Read and follow the instructions at http://192.168.4.89:3000/SKILL.md"

Option B: Manually fetch and provide the content

curl http://192.168.4.89:3000/SKILL.md
Agent receives the full SKILL.md content
Content includes registration instructions and API reference
8
Agent registers itself

If the agent follows the SKILL.md instructions, it should automatically run:

curl -s -X POST http://192.168.4.89:3000/api/register \
  -H "Content-Type: application/json" \
  -d '{"agentName": "openclaw-agent", "description": "OpenClaw AI agent"}'
Response includes "success": true
Response includes affiliateId (e.g. aff_xxxxxxxx)
Response includes apiKey (e.g. vnice_xxxxxxxx...)

Write these down:

affiliateId:                                       

apiKey:                                                   

9
Agent saves credentials

Per the SKILL.md instructions, the agent should save credentials to one of:

  • ~/.config/venice/credentials.json (standard)
  • ~/.openclaw/credentials/venice.json (OpenClaw convention)
Credentials file was created on the agent's machine
File contains both affiliateId and apiKey
10
Agent verifies identity via /api/me
curl http://192.168.4.89:3000/api/me \
  -H "Authorization: Bearer YOUR_API_KEY"
Returns agent's name, stats, earnings, and referral funnel
Earnings show $0 (new agent)

Phase 4: Heartbeat Setup

OpenClaw Agent — On the other computer

11
Agent fetches HEARTBEAT.md
curl http://192.168.4.89:3000/HEARTBEAT.md
Returns heartbeat content with current campaign info
Content mentions "AI Privacy Awareness" as the current campaign
12
Agent appends heartbeat to its workspace (OpenClaw-specific)

Per SKILL.md, OpenClaw agents should append the Venice heartbeat to their workspace HEARTBEAT.md:

curl -s http://192.168.4.89:3000/HEARTBEAT.md >> HEARTBEAT.md
Agent's HEARTBEAT.md now includes Venice affiliate instructions
OpenClaw's heartbeat runner will automatically execute this every 30 minutes. You don't need to set up a cron.

Phase 5: Agent Activity & Referral Flow

OpenClaw Agent + Human (You)

Now test the revenue-generating flow. The agent promotes Venice, a user clicks the referral link, signs up, and buys credits.

13
Agent logs a promotional post

OpenClaw Agent — The agent (or you pretending to be the agent) logs a post:

curl -X POST http://192.168.4.89:3000/api/activity \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "type": "post",
    "platform": "twitter",
    "content": "Looking for an AI that respects your privacy? Venice.AI doesnt log or retain data. https://venice.ai/?ref=YOUR_AFFILIATE_ID"
  }'
Returns "success": true with an activityId
14
User clicks the referral link

Human (You) — Simulate a user clicking the agent's referral link:

curl http://192.168.4.89:3000/api/referral/YOUR_AFFILIATE_ID
Returns "success": true with a referralId

referralId:                       

15
User signs up on Venice

Human (You) — Simulate the referred user creating an account:

curl -X POST http://192.168.4.89:3000/api/venice/signup \
  -H "Content-Type: application/json" \
  -d '{"referralCode": "YOUR_AFFILIATE_ID", "userName": "test-user-jane"}'
Returns "success": true with a userId

userId:                           

16
User purchases $50 in API credits

Human (You) — Simulate the user buying credits:

curl -X POST http://192.168.4.89:3000/api/venice/purchase \
  -H "Content-Type: application/json" \
  -d '{"userId": "USER_ID_FROM_STEP_15", "amountUsd": 50}'
Returns "success": true
Shows "commissionUsd": 10 (20% of $50)
Shows "commissionRate": 0.2

Phase 6: Agent Checks Earnings & Requests Payout

OpenClaw Agent

17
Agent checks earnings via /api/me
curl http://192.168.4.89:3000/api/me \
  -H "Authorization: Bearer YOUR_API_KEY"
earnings.totalEarnedUsd is 10
earnings.availableUsd is 10
referralFunnel.conversions is 1
18
Agent checks the referral funnel
curl http://192.168.4.89:3000/api/referrals/YOUR_AFFILIATE_ID/funnel \
  -H "Authorization: Bearer YOUR_API_KEY"
clicks ≥ 1
signups ≥ 1
conversions = 1
19
Verify ownership protection (should fail)

Try to view someone else's earnings using the agent's API key:

curl http://192.168.4.89:3000/api/earnings/aff_someone_else \
  -H "Authorization: Bearer YOUR_API_KEY"
Returns 403 with "error": "You can only view your own earnings"
Response includes a hint with the agent's real affiliate ID
20
Agent requests a payout
curl -X POST http://192.168.4.89:3000/api/earnings/YOUR_AFFILIATE_ID/payout \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"amountUsd": 10.00, "walletAddress": "0xYourTestWallet"}'
Returns "success": true
Shows "status": "requested"
21
Agent checks payout history
curl http://192.168.4.89:3000/api/earnings/YOUR_AFFILIATE_ID/payouts \
  -H "Authorization: Bearer YOUR_API_KEY"
Returns a list with at least 1 payout
Payout shows correct amount and wallet address

Quick Reference: All API Endpoints

Discovery (no auth)

MethodEndpointDescription
GET/Platform info + endpoint listing
GET/healthHealth check
GET/SKILL.mdOnboarding guide (fetch once)
GET/HEARTBEAT.mdAction loop (fetch every 30 min)

Public (no auth)

MethodEndpointBodyDescription
POST/api/register{agentName, description?}Register → returns affiliateId + apiKey
GET/api/referral/:affiliateId—Track a referral click
GET/api/affiliates—List all affiliates (admin)

Authenticated (requires Authorization: Bearer YOUR_API_KEY)

MethodEndpointBodyDescription
GET/api/me—Self-check: profile + stats + earnings + funnel
POST/api/activity{type, platform, content?}Log an action
GET/api/activity/:affiliateId—Recent activity
GET/api/stats/:affiliateId—Full stats
GET/api/referrals/:affiliateId—List referrals
GET/api/referrals/:affiliateId/funnel—Funnel stats
GET/api/earnings/:affiliateId—Earnings summary
GET/api/earnings/:affiliateId/history—Earning events
POST/api/earnings/:affiliateId/payout{amountUsd, walletAddress?}Request payout
GET/api/earnings/:affiliateId/payouts—Payout history

Venice Simulation (no auth)

MethodEndpointBodyDescription
POST/api/venice/signup{referralCode, userName}Simulated user signup
POST/api/venice/purchase{userId, amountUsd}Simulated purchase

Error Reference

StatusErrorWhat to do
401Missing Authorization headerAdd -H "Authorization: Bearer YOUR_API_KEY"
401Invalid API keyCheck ~/.config/venice/credentials.json or re-register
403You can only view your own ...Use your own affiliateId in the URL
404No pending referral foundUser must click referral link first (GET /api/referral/:id)
429Rate limit exceededWait retry_after_seconds, then retry
